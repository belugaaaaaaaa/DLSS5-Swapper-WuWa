# 鸣潮轻量部署助手

**预览说明：部署助手与轻量发布包正在完成最终打包、解包和入口验证。** 这里介绍计划发布的使用流程；是否已有可下载资产，以 [GitHub Releases](https://github.com/belugaaaaaaaa/DLSS5-Swapper-WuWa/releases) 为准。源码 ZIP 本身不含构建好的插件，不能直接用来安装。

目标是让玩家更容易尝试减少 NR 的额外显卡负担，同时保留自己满意的画质。这个入口不要求编译，也不需要让 Swapper 常驻。原生插件沿用本项目已公开的算法和 F8 控制；它会在本机绑定你明确选择的鸣潮主程序完整路径。

## 下载、解压、打开

1. 从 Releases 下载名称为 `DLSS5-Swapper-WuWa-<版本>.zip` 的**部署助手包**，解压到一个普通本地文件夹。不要解压到鸣潮游戏目录或部署工具的缓存目录里。
2. 关闭鸣潮及它的启动器，在解压后的根目录双击 **`Start-Setup.cmd`**。
3. 点击“选择目录”，选择包含 **`Wuthering Waves Game`** 文件夹的鸣潮根目录。工具核对的主程序是其下 `Client/Binaries/Win64/Client-Win64-Shipping.exe`；请选择真正的 64 位鸣潮安装。
4. 组件来源默认“自动从官方 v2.2.7 下载”。若已有未经修改的官方 `DLSS5-Swapper-2.2.7-portable.exe`，可点击“选择已有包”。两种方式都会核对固定哈希；工具不运行原版 EXE。
5. 查看“许可与组件来源”，了解相关游戏规则，然后勾选同意并点击 **“一键安装 / 修复”**。
6. 等窗口显示安装完成，再启动鸣潮，按 **F8** 查看实际状态和设置。部署助手可以关闭。

首次准备通常需要联网：工具下载便携 Node.js、原版 Swapper 和 7-Zip 提取工具，校验后留在本机缓存。已有原版 EXE可以避免再次下载这个包；Node.js 和提取工具在缓存尚未准备时仍需取得。准备完整且未被修改的缓存以后，重新安装可以复用它。

## 进游戏后怎样调节

F8 提供 NR 开关、每次刷新/缓存模式和处理比例。首次缺少相应设置时使用 **85% 处理比例、缓存模式**；已有设置保留。每次 NR、缓存尝试和实际缓存命中是不同状态，面板打开或显示开关已开，不能单独证明模型和缓存已经运行。

先看自己熟悉的场景、人物、暗部和快速转向，再比较满意画质下的风扇、功耗与帧时间。如果能对照，保持分辨率、游戏画质、DLSS/插帧及 FPS 上限一致，分别观察 NR 关闭、每次刷新和缓存模式。没有仪器也可以反馈风扇感受，未知数据直接注明未知。见 [玩家指南](PLAYERS.zh-CN.md) 与 [对照测试方法](GAME_VALIDATION.zh-CN.md)。

缓存条件不满足时继续正常 NR；某些拒绝复用的像素使用当前 DLSS 图像，因此运动中的增强变化、拖影或闪烁值得反馈。没有适用于所有机器的固定降耗百分比。

## 修复、更新与卸载

- **修复或重装**：关闭游戏，再用同一个助手选择同一个根目录，点击“一键安装 / 修复”。已有个人设置会保留，不通过重新安装强制重置 NR。
- **更新助手**：将新发布包解压到独立文件夹，按新版本说明安装。已知插件升级需要发布包内可校验的旧版本来源；无法确认来源时工具会拒绝覆盖。不要为了继续安装手工删除未知文件或旧备份。
- **卸载**：关闭游戏，选择原根目录，点击“卸载鸣潮插件”。只处理本项目管理的插件及相关插件配置，保留游戏原文件和历史备份记录；个人调节记录用于之后重装。它不会借此恢复上游历史安装曾替换的游戏 SR DLL。

此助手只支持鸣潮的 Native DLSS / DirectX 12 路线。未知 loader、运行库或插件、定向到其他位置的 addon 搜索配置、未完成事务、正在运行的游戏和无法可靠检查的目录会阻止安装，并显示原因。工具不会用删除所有 addon 的方式绕过这些检查，也不会替换游戏自带的 `nvngx_dlss.dll`、`sl.dll`、EXE、PAK 或游戏画质设置。

## 包内有什么

部署助手 ZIP 包含本版本受 Git 追踪的完整源码、部署入口、自己的原生插件模板、F8 插件、小型 JavaScript 生产依赖及完整许可。**不含 NVIDIA 运行库或模型、原版 Swapper EXE、游戏文件、Node.js EXE、7-Zip EXE 或编译器。** 这些运行所需外部组件由玩家按固定来源在本机取得。

模板尚未绑定游戏路径。安装器确认你选择的主程序后，在本机生成对应路径的插件，并核对模板来源、绑定结果、版本和哈希。源码、模板元数据及公开发行记录不包含开发者的私人安装路径。

## 验证范围

目前部署工具的 26 项核心测试和 27 项目标绑定测试通过。隔离工作区的实际生产 worker 使用便携 Node.js、Windows 进程/路径检查、真实模板与官方提取资源，完成准备、安装、重装、离线卸载和离线重装；NR 关闭和 67% 处理比例保留，测试目标的 SR、Streamline、EXE、PAK 及游戏设置哈希保持不变。这个目标是用于文件部署测试的隔离 PE 文件，**没有启动鸣潮或执行 NR 模型**。

最终 ZIP 的独立解包、图形入口与同一部署核心验证结果仍待完成后补充。已安装本地版本的用户验收另见 [已有实测记录](USER_VALIDATION.zh-CN.md)，不能据此把所有玩家硬件或新发布包都写为游戏验收通过。

## 遇到问题

下载或校验失败时，本次不会靠未经校验的组件继续安装。可以稍后重试，或选择哈希匹配的官方已有包。若提示缓存被修改，按提示选择独立的新缓存目录；若提示未知文件、异常 addon 路径或未完成事务，保留现状与备份，先提交问题。

通过 [问题反馈](https://github.com/belugaaaaaaaa/DLSS5-Swapper-WuWa/issues/new?template=quality-or-bug.zh-CN.md) 描述窗口提示、版本与操作步骤即可，不必上传原始日志。需要截图时遮住 UID、用户名和个人路径；可分享的状态记录也先去掉本机路径。有效减负、无收益或画质取舍可以提交 [玩家实测反馈](https://github.com/belugaaaaaaaa/DLSS5-Swapper-WuWa/issues/new?template=player-test.zh-CN.md)。
