# 相比 Swapper v2.2.7 的修改

对照基础为 Swapper tag v2.2.7 / commit `3b3b0efb5472df7fc806d7aff31c1d95819500c5`。NR 的基础实现同时来自 RenoDX 与 Generic；以下不是 NVIDIA 模型训练或权重修改。

## 1. 允许安全复用 NR 结果

完整 NR 产生新结果时，保存增强 RGB、参考 RGB、深度及有效性。在允许复用的下一次基础 DLSS 调用上，用运动信息重投影历史结果，并用当前参考图像与历史参考图像之差修正颜色。设计中的表达式为 `editedWeighted + (currentReference - referenceWeighted)`。

这是 GPU 历史缓存算法。没有重训练模型，也没有把原生 DLSS 插帧算法移植到鸣潮。刷新节奏基于基础 DLSS 调用，不按 Present 或生成帧计数。

运动、深度、颜色、亮度、越界和非有限数值检查不通过时，对应像素回到当前 DLSS 结果。新生成的 NR RGB 不做任意截断；测试覆盖了半精度、暗 HDR、SDR 及颜色抵消情况。复用可能影响增强效果和时序稳定性，仍需要游戏实测。

## 2. 限定鸣潮调用路径

原生插件使用使用者本地编译时传入的完整主程序路径；默认空路径不启用。只有匹配进程、DX12、SR 后、指定基础特征及单次处理条件同时成立才可使用缓存。

路径配置公开化是整理源码时的变更。安装元数据必须与选择的鸣潮目标一致，不能只凭可执行文件同名就启用。源码包不含个人游戏路径。

## 3. 失败时退避，避免缓存本身增加持续开销

先观察两次稳定调用，只有确认上一份 GPU 工作实际提交并完成才可复用，不阻塞 CPU 等待 GPU。连续三次未命中后暂停缓存 120 次基础求值，后续失败将观察间隔增加到 240、480、960。暂停期间继续普通 NR，不执行额外缓存工作。

刷新和复用分别积累至少四个实际完成的 GPU 时间样本后，若复用时间达到刷新时间的 80%，也进入退避。排队、录制、成功求值和 GPU 完成是不同状态，不能混用。

这一机制减少无效尝试，不能保证 NR 总成本下降。帧并行情况下缓存命中率可能很低。它不会自动关闭 NR、强制降画质或限制 FPS。

## 4. F8 面板直接控制插件

新增版本化 C 接口：`RenoDX_WuWa_GetState` 和 `RenoDX_WuWa_SetControl`。面板可以设置 NR、每次刷新/缓存模式，以及已有的 50/67/75/85/100 名义处理比例。

命令使用有界队列，并通过请求编号和状态回读确认生效。面板不会把“命令已排队”写成“已经执行”，也不会在插件尚未运行或错误时显示虚假的已开启。面板不依赖 Swapper 常驻、Electron 管道或私有内存偏移。

## 5. Swapper 安装、保留设置与卸载

鸣潮走独立 Native/DX12 插件流程，不沿用通用换 SR DLL 的路线。仅升级已知且可验证的插件文件；遇到未知代理或插件文件时拒绝覆盖。检查 ReShade 插件路径与禁用规则，避免安装后被静默禁用。

重新安装和卸载保留既有设置、备份记录。卸载只处理本项目插件，不恢复或替换原有游戏 DLL。历史上其他工具进行的 DLL 替换不由本仓库重新定义为原始状态。

启动器注明本地鸣潮适配版本并抑制上游自动覆盖提示。隐藏 Electron 面板没有连接的客户端时停止绘制。

## 6. 可复现测试与诚实边界

仓库公开了固定依赖、编译脚本、控制测试、CPU 数值参考、GPU shader 检查及合成输入耗时。所有测试均注明是否包含真实模型、游戏或整帧。

尚未做实际鸣潮 A/B 验收，不能承诺开启后的温度、功耗或风扇转速改善，也不能宣称保持了与原版完全相同的画质。显著降低 NR 额外耗时是研发目标，尚不是达成的实测结果。
