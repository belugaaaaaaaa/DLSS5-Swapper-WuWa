# 实际鸣潮验收方法

当前已获得使用者在实际鸣潮中的使用验收及 NR 执行日志，见 [用户实测记录](USER_VALIDATION.zh-CN.md)。以下固定条件的系统性对照仍未完成，用于进一步量化性能、功耗和画质变化。

## 对照条件

同一场景、分辨率、画质、DLSS/插帧、帧率上限及相近温度条件，比较 NR 关闭、NR 每次刷新、NR 缓存三个状态。每次先预热，再采样相同时间；记录场景、显示分辨率、设置、驱动、插件来源和真实执行状态。

若只查看 GPU 利用率，无法证明节能。记录功耗、温度、风扇、帧率、帧时间以及有效采样时长；程序换进程或退出后停止该组采样。实际帧率需要游戏或独立帧时间工具，不能从 NVIDIA 功耗采样推断。

## 执行与画质

先确认正确进程中的插件加载、模型实际执行、F8 请求及状态回读。随后观察缓存实际复用次数、未命中和退避。设置已打开不等于模型运行，命令排队不等于已生效。

画质至少包含静止细节、快速转向、战斗特效、人物/草木运动、遮挡解除、字幕/HUD、暗部及 HDR/SDR。对比拖影、闪烁、边缘、人物外观和局部增强消失。保存相同条件的截图或片段，并明确测试者判断；仅数值 shader 检查不能代替视觉验收。

## 记录结果

报告三组条件和数据，再说明差异是否超过运行波动。约 30% 的 NR 额外 GPU 耗时下降仅作为研发目标；未达到时如实记录。只有场景与条件一致的数据，才能支持该条件下的性能或功耗结论；不得推广成所有显卡、所有场景或保证风扇安静。
