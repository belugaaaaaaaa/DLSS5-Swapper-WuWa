# 社区研发方向

目标是让更多玩家以满意的画质，减少神经渲染造成的额外显卡负担。以下是后续工作的优先级，不是已经交付的功能清单。

## 1. 让玩家更容易参与和使用

当前源码与本地构建流程已经公开，已有用户实际验收。下一步需要降低构建和目标路径配置的门槛、完善安装检查与恢复说明，并研究可验证的插件分发流程，让玩家更容易获得与自己安装环境匹配的版本。第三方运行库与模型继续遵守各自许可证。

玩家可以提交“我的显卡、分辨率、游戏版本和希望解决的问题”，帮助决定先适配哪些常见配置。构建方式改进时仍要保留目标匹配与未知文件保护。

## 2. 找出哪些配置真正有收益

汇总固定场景与设置下的 NR 关闭、每次刷新、缓存模式对照。体验、画质、功耗和帧时间分别记录；数据不足的反馈也保留其适用范围。整理时区分单点截图、用户感受和完整采样，不把生成帧计数当作基础渲染性能。

逐步形成按显卡、分辨率、驱动和场景归纳的配置经验。所有“有效”或“无收益”的结论都附条件，帮助玩家选择，而不是只收集最好看的数字。

## 3. 减少无效计算，同时检查画质

优先研究真实游戏中的缓存命中、GPU 完成条件、失败退避和资源开销。缓存本身不划算时，应减少额外工作。算法收益需要结合快速转向、战斗、遮挡解除、暗部和 HDR/SDR 的视觉检查。

画质与负担的取舍由玩家明确选择。新增参数要说明用途和代价；避免把额外计算默认叠加到用户的游戏里。

## 4. 在证据基础上扩大适配

先扩充鸣潮不同显卡、驱动、分辨率和游戏版本的实测，再评估其他游戏的调用路径与资源契约。只有源码可以编译或插件可以加载，还不足以声明对应配置已经适配。

欢迎提交实测与改进提案，入口见 [贡献指南](../CONTRIBUTING.md)。代码贡献应说明解决了哪种玩家负担、如何验证收益和画质，以及哪些条件仍需要社区测试。
